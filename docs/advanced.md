## Advanced Operations

### Middleware ordering for body capture

If body capture is enabled, install observability before other middleware:

```python
from fastapi.middleware.cors import CORSMiddleware
from fastapiobserver import SecurityPolicy, install_observability

install_observability(app, settings, security_policy=SecurityPolicy(log_request_body=True))
app.add_middleware(CORSMiddleware, allow_origins=["*"])
```

### Multi-worker Gunicorn

With `--preload-app`, gunicorn imports your app, and so runs `install_observability()`, in the master process, then forks the workers. Threads don't survive a fork, so each worker starts a new log writer thread after the fork, with fresh locks and an empty queue. Logs work with or without `--preload-app`. The event-loop watchdog and the thread-pool watcher start in each worker's lifespan.

OpenTelemetry's batch processors restart their threads after a fork too. gRPC channels created before a fork don't work reliably in the child, though. With `--preload-app` and tracing or OTLP logs on, set `OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf`, or leave `--preload-app` off.

#### Prometheus Multiprocess Mode

If you are using Prometheus with multiple Gunicorn workers, you must configure a shared metrics directory:

```bash
export PROMETHEUS_MULTIPROC_DIR=/tmp/prometheus-metrics
rm -rf "$PROMETHEUS_MULTIPROC_DIR"
mkdir -p "$PROMETHEUS_MULTIPROC_DIR"
```

`gunicorn.conf.py`:

```python
from fastapiobserver import mark_prometheus_process_dead


def child_exit(server, worker):
    mark_prometheus_process_dead(worker.pid)
```

### Bounded queue and overflow policy

Use queue controls to define behavior under sustained log pressure:

```python
settings = ObservabilitySettings(
    app_name="orders-api",
    service="orders",
    environment="production",
    log_queue_max_size=20000,
    log_queue_overflow_policy="drop_oldest",  # or "drop_newest" / "block"
    log_queue_block_timeout_seconds=0.5,
)
```

Queue pressure metrics exposed on `/metrics` (Prometheus mode):
- `fastapiobserver_log_queue_size`
- `fastapiobserver_log_queue_capacity`
- `fastapiobserver_log_queue_overflow_policy_info`
- `fastapiobserver_log_queue_enqueued_total`
- `fastapiobserver_log_queue_dropped_total{reason="drop_oldest|drop_newest"}`
- `fastapiobserver_log_queue_blocked_total`
- `fastapiobserver_log_queue_block_timeouts_total`
- `fastapiobserver_threadpool_busy`, `fastapiobserver_threadpool_limit` and `fastapiobserver_threadpool_waiting`: AnyIO's thread pool, which runs sync endpoints and dependencies. See [full thread and database pools](logging.md#full-thread-and-database-pools).
- `fastapiobserver_db_pool_checked_out{engine}` and `fastapiobserver_db_pool_limit{engine}`: each SQLAlchemy `QueuePool` passed as `db_engine`.
- `fastapiobserver_log_bytes_total{route}`: bytes of JSON log lines written, by the route template of the request that wrote them. Lines written outside a request are counted as `<none>`, and requests that matched no route as `<unmatched>`. A line written to several sinks counts once. Use it to see which routes drive your log bill.

### Sink circuit breaker

Every output sink is wrapped with a circuit breaker so a failing sink does not
degrade request-path logging. This includes custom sinks.

To send logs somewhere else, write a class with a `name` and a
`create_handler(formatter)` method (the `LogSink` protocol), and register it
before calling `install_observability()`. Its handler gets the same redacted
JSON lines as stdout, on the log queue's listener thread:

```python
from fastapiobserver import register_sink

register_sink(MySink())
install_observability(app, settings)
```

```python
settings = ObservabilitySettings(
    app_name="orders-api",
    service="orders",
    environment="production",
    sink_circuit_breaker_enabled=True,
    sink_circuit_breaker_failure_threshold=5,
    sink_circuit_breaker_recovery_timeout_seconds=30.0,
)
```

Breaker metrics exposed on `/metrics`:
- `fastapiobserver_sink_circuit_breaker_state_info{sink,state}`
- `fastapiobserver_sink_circuit_breaker_failures_total{sink}`
- `fastapiobserver_sink_circuit_breaker_skipped_total{sink}`
- `fastapiobserver_sink_circuit_breaker_opens_total{sink}`
- `fastapiobserver_sink_circuit_breaker_half_open_total{sink}`
- `fastapiobserver_sink_circuit_breaker_closes_total{sink}`

### Logging Shutdown Lifecycle

When the app's lifespan ends, `install_observability()` waits for queued log
records to be written, flushes the outputs and flushes OpenTelemetry providers.
Logging and providers keep running, because other apps in the process share
them and a reused `TestClient` starts the app again. They're stopped at process
exit: logging by its `atexit` hook, OpenTelemetry providers by their own.

For explicit control during the App lifecycle, we highly recommend wrapping your app's lifespan with the newly provided `observability_lifespan`:

```python
from fastapiobserver import observability_lifespan

@asynccontextmanager
async def lifespan(app: FastAPI):
    # Prepare app dependencies
    async with observability_lifespan(app):
        yield # App receives traffic
    # All background threads gracefully flushed here
```

### Runtime Stress Harness

For operational hardening after touching logging/lifecycle code paths, run:

```bash
uv run python scripts/runtime_stress.py --profile standard
```

This script validates:
- repeated install/lifespan teardown cycles
- queue overflow behavior (`drop_oldest`, `drop_newest`, `block`)
- thread-contention setup/shutdown safety
- fork replay safety (no duplicated pre-fork log records)
- isolated subprocess execution for fork replay checks (avoids noisy multi-threaded `os.fork()` warnings in the main run)

Use `--profile deep` for prolonged soak testing before major releases.

### Loguru Coexistence

If your service already uses `loguru`, forward those logs into
`fastapi-observer` instead of maintaining two independent pipelines.

```python
from fastapiobserver import install_loguru_bridge

# loguru -> stdlib -> fastapi-observer queue/sinks
bridge_id = install_loguru_bridge()
```

Detailed migration/coexistence guide: [`loguru.md`](loguru.md)
